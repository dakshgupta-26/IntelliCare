# IntelliCare ML & Optimization Service

Python service behind the IntelliCare dashboard. It implements the core objectives of the project synopsis (FF-180):

| Objective | Implementation | Code |
|---|---|---|
| Demand forecasting (2/6/12/24 h) | LSTM (PyTorch) + XGBoost per ICU / General Ward / Emergency, 95% intervals | `app/forecasting.py` |
| No-show + consultation-duration prediction | Random Forest vs XGBoost, fairness audit (demographic parity) | `app/appointments.py` |
| Constraint optimization | OR-Tools MILP (SCIP) for beds / nurses / overtime / ventilators; CP-SAT for appointment slotting | `app/optimization.py` |
| RAG policy engine | TF-IDF vector index over hospital SOPs, citations, optional Claude synthesis | `app/rag.py`, `data/sops/` |
| Dynamic rescheduling + what-if simulation | Cancellation / emergency override / doctor unavailable; crisis scenarios | `app/clinic.py`, `app/scenario.py` |
| Human-in-the-loop + audit | Approve / modify / reject recommendations, decision log | `app/main.py` |
| Fail-safe fallbacks | Priority-rule allocator and scheduler if a solver fails; extractive answers if the LLM is unavailable | `optimization.py`, `rag.py` |

The data is **synthetic** (`app/data_gen.py`): two years of hourly bed census with daily/weekly/seasonal cycles and surge events, and 40,000 outpatient appointments with realistic no-show behaviour. Real patient-level hospital data isn't publicly available; the models only ever see the generated rows, never the generating formulas.

## Setup

Requires [uv](https://docs.astral.sh/uv/). It installs Python 3.11 and all dependencies automatically.

```bash
cd ml-service
uv sync
uv run python train.py        # ~3 min: generates data, trains all models, writes reports/metrics.md
uv run uvicorn app.main:app --port 8000
```

macOS only: XGBoost needs OpenMP (`brew install libomp`).

Then run the frontend from the repo root (`npm run dev`). It calls the service at `http://localhost:8000`; override with `VITE_ML_API_URL` in a root `.env`. Interactive API docs: http://localhost:8000/docs

### Optional: LLM answers in the policy assistant

```bash
export ANTHROPIC_API_KEY=...   # without it, the assistant returns extractive answers from the SOPs
```

The model defaults to `claude-opus-5` (override with `INTELLICARE_LLM_MODEL`).

## Results

See `reports/metrics.md` (regenerated by `train.py`). Headlines on held-out data:

- Forecasting MAPE 2–5% across units and horizons. Both models beat the naive persistence baseline at every horizon from 6 h onward. At 2 h, XGBoost beats it in every unit, but the LSTM trails persistence for ICU.
- No-show ROC-AUC 0.67. Duration MAE 2.8 min vs 4.4 min for fixed department slots.
- Fairness audit passes: high-risk flag rates differ by 0.3 points across gender and 2.5 points across age bands. Age and gender are deliberately not model inputs; adding age would gain 0.009 AUC but widen the age gap to 15 points.
- Scheduling: on a simulated 260-request clinic day, the optimized schedule sees more patients and waitlists fewer than static fixed slots, at similar wait times.

## Layout

```
app/
  config.py         units, capacities, departments, horizons
  data_gen.py       synthetic datasets
  forecasting.py    LSTM + XGBoost training and inference
  appointments.py   no-show / duration models + fairness audit
  optimization.py   OR-Tools MILP + CP-SAT, with rule-based fallbacks
  clinic.py         simulated OPD day, rescheduling events, wait-time metrics
  scenario.py       what-if crisis simulation
  rag.py            SOP retrieval + answer generation
  main.py           FastAPI endpoints
data/sops/          hospital SOP corpus (7 documents)
train.py            one-command data generation + training + report
```
